# 用户验证记录和洞察

> 文档属性：对外展示材料。适合作为作品集中的用户验证证据，展示小样本探索、关键反馈和产品判断。

## 验证性质

本轮用户验证是小范围探索性测试，不作为统计性结论。目标是发现早期用户对产品定位、核心链路和 AI 功能边界的理解情况，并为后续 AI 输出评测和 Demo 打磨提供依据。

测试时间：2026-06-27  
整理时间：2026-06-28  
测试样本：目标用户小样本探索性测试，覆盖刚毕业大学生与职场新人  
测试方式：线上视频  
用户范围：刚毕业大学生 / 职场新人  
共同特征：有阅读拖延、自我提升或求职成长动机，使用过 AI 问答产品。

## 测试任务

1. 从首页开始一次低压力阅读。
2. 阅读中遇到不理解的概念时，尝试使用阅读辅助里的“直接问”。
3. 结束阅读后查看 AI 今日总结，并说说它是否有帮助、是否像作业。

## 共性正反馈

| 观察点 | 用户反馈 | 产品判断 |
| --- | --- | --- |
| 低压力启动 | 用户普遍认可 5 分钟启动阻力低 | “每天先读 5 分钟”的核心定位可以保留 |
| 页面风格 | 用户普遍认为界面简洁、路径清晰 | 当前 V0.1 Demo 的极简主线有效 |
| 直接问 | 用户认为能减少跳出 App 查询 | 直接问是阅读中高价值 AI 节点 |
| 今日总结 | 用户认为有鼓励和复盘价值，不像作业 | 今日总结符合低压力读后收束定位 |

## 关键用户原话

> U01：感觉这个回答挺充分的，还举了一个好理解的小例子，就是格式有点挤了感觉。

> U02：路径清晰，没有感觉到繁琐。

> U02：看不太懂这个直接问是什么意思。

> U03：可以减少我跳出这个软件的概率，感觉挺有用的。

> U03：感觉这一块更像是鼓励和复盘，就是等待时间有点长了。

## 发现的问题

### 1. 直接问和基于原文回答的边界需要更强引导

用户对“直接问”的入口价值认可，但不是每位用户都能立刻理解它和“基于原文回答”的区别。

产品判断：

- 直接问适合术语、概念、背景知识。
- “这段 / 这里 / 作者这句话”这类问题应引导到“基于原文回答”。
- 后续需要在入口文案、输入占位和错误引导里进一步强化边界。

### 2. 直接问输出内容有帮助，但格式需要更利于阅读中快速扫读

用户认可回答正确和例子有帮助，但出现“格式有点挤”的反馈。

产品判断：

- 阅读中 AI 辅助不是长聊天，应更像轻量解释卡片。
- 输出应优先保持短、清楚、有例子。
- 前端展示可以考虑把 answer / example / returnHint 做更明显的层次分隔。

### 3. 今日总结有价值，但长内容场景要关注等待时间

用户认为今日总结像鼓励和复盘，不像作业；但在文本内容较多时等待时间会变长。

产品判断：

- 今日总结仍值得保留为第一批真实 AI 节点。
- 需要继续评估 flash / pro 路由、延迟和结构化输出稳定性。
- 不应为了缩短等待而删减用户确认阅读范围内的有效内容。

### 4. 首次阅读中的返回和退出心智可以后置优化

有用户在阅读页寻找快捷回到首页的退出按钮，但这不是本轮最高优先级问题。

产品判断：

- 当前优先级低于 AI 输出格式、AI 功能边界和今日总结延迟。
- 后续可在 UI 打磨阶段优化首次阅读的安全感提示。

## 优先级判断

| 类型 | 结论 |
| --- | --- |
| 优先保留 | 低压力启动、极简阅读体验、AI 直接问、AI 今日总结 |
| 优先修改 | 直接问与基于原文回答的边界引导、直接问输出格式、今日总结长内容延迟 |
| 暂缓推进 | 宠物系统进一步丰富、首次阅读退出按钮强提示、基于原文回答 live 接入 |
| 继续验证 | 卡通风格是否过重、奖励系统是否需要增强、不同书籍内容下 AI 总结质量 |

## 结论边界

本轮只能说明：目标用户对低压力阅读启动、直接问和今日总结有早期正反馈，并暴露了 AI 边界引导、输出格式和延迟问题。

暂不声称：

- 已证明用户会长期留存。
- 已验证付费意愿。
- 样本代表所有目标用户。
- AI 输出质量已经稳定到正式上线标准。

## 项目价值

这轮验证可以证明：项目不是只停留在主观设计，而是用真实目标用户反馈校准产品取舍。用户反馈直接推动了下一步 AI 质量评测：重点检查直接问的边界拦截、输出格式，以及今日总结在长内容下的延迟和结构化稳定性。
