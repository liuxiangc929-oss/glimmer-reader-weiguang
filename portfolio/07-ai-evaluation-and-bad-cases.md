# AI 评测与 Bad Case

> 文档属性：对外展示材料。适合作为作品集中的 AI 质量评测证据，展示模型输出、边界控制、路由策略和 Bad Case 迭代。

## 评测目标

本轮评测验证 AI 今日总结和直接问是否符合产品定位：温和、低压力、清晰、可控，并能服务阅读理解和读后复盘。

当前不评测“基于原文回答”的真实能力。该功能只保留 mock、schema 和未来扩展边界，等上下文范围、引用方式、越界处理和回答风格确认后再进入 live 接入。

评测时间：2026-06-28  
评测范围：AI 直接问、AI 今日总结  
评测方式：DeepSeek live 调用 + 本地 schema / fallback / cache 验证  
评测样例：直接问 10 条，今日总结 8 条  
原始评测记录保留在本地，作品集中只呈现脱敏后的样例、结论和迭代判断。

## 评测维度

| 维度 | 关注点 |
| --- | --- |
| 输出准确性 | 概念解释是否清楚，今日总结是否基于提供内容 |
| 风格匹配 | 是否温和、低压力、不像作业 |
| 结构稳定 | 是否符合 JSON schema 和固定字段 |
| 边界控制 | 直接问是否不假装看过原文，能否拦截上下文依赖问题 |
| 模型路由 | 简单问题走 flash，复杂问题 / 长内容走 pro |
| 延迟与缓存 | 今日总结是否可缓存，长内容等待是否可接受 |
| 失败兜底 | 失败时是否温和 fallback，不暴露技术错误 |

## 结果概览

| 评测项 | 结果 |
| --- | --- |
| 直接问基础解释 | 多数可用，能给出简短解释和生活化例子 |
| 直接问上下文拦截 | “这里作者为什么这么说”“结合这段原文”已被拦截 |
| 直接问模糊短问 | 首轮“这个什么意思”未被前置拦截；已修复为 `needs_context`，不再调用 live |
| 今日总结短内容 | 结构稳定，quote + 3 items，语气整体温和 |
| 今日总结缓存 | 相同输入二次请求命中缓存 |
| 今日总结长内容 | pro 路由触发，但长内容 live 仍可能 fallback；fallback 文案已优化，不再截半句话 |
| 模型路由 | 概念对比已切 pro；同时收窄通用关键词，避免普通短总结误切 pro |

## 代表性通过样例

### 直接问：术语解释

用户问题：

```text
蔡加尼克效应是什么？
```

模型输出摘要：

- 解释：未完成任务更容易被记住。
- 例子：电视剧在关键处结束，会更惦记下一集。
- 评价：清楚、短、有例子，适合作为直接问的基础通过样例。

### 今日总结：短内容总结

输入内容：关于专注力边界、疲惫和调整节奏。

模型输出摘要：

- quote：专注力会疲惫，那是大脑在提醒你照顾好自己。
- 三个要点分别覆盖：专注力有限、疲惫不是失败、允许休息。
- 评价：结构稳定，语气温和，符合读后收束定位。

## Bad Case 讲述价值

| 优先级 | Bad Case | 面试讲述价值 |
| --- | --- | --- |
| 必讲 | 模糊短问没有被直接问拦截 | 最能体现 AI 产品经理对用户输入、功能边界和路由策略的判断 |
| 可讲 | 部分复杂输入未按预期切 pro | 能体现成本、质量、延迟之间的模型路由取舍 |
| 补充说明 | 长内容今日总结触发 schema / fallback | 偏工程和稳定性细节，适合在追问真实 AI 接入风险时展开 |

本轮 AI 评测不是为了证明模型完美，而是为了发现真实上线前必须处理的边界、路由和 fallback 问题。

## 典型 Bad Case 1：长内容今日总结触发 schema fallback

功能：AI 今日总结  
caseId：DS-04  
输入类型：长内容，多段重复论述，预期走 pro  
实际结果：触发 pro，thinking enabled，但最终返回 mock fallback，原因是 `schema_error`。

问题表现：

- 长内容确实进入 pro 路由，说明路由方向正确。
- 但结构化 JSON 没有稳定通过校验，导致用户看到 fallback 总结。
- fallback 内容可用但偏模板化，其中一个 item 被截断，阅读收束感弱。

问题归因：

- 长输入 + pro thinking 后，模型结构化输出稳定性不足。
- 当前 schema 校验较严格，但缺少“结构修复 / 一次重试”机制。
- fallback 仍然带有截断痕迹，和“今日总结不删有效内容”的产品原则不完全匹配。

修改策略：

- 强化 daily summary prompt 的 JSON-only 约束。
- 对 summary 增加一次轻量 JSON 修复或重试，不重发全部上下文时要谨慎评估。
- 优化 fallback：避免截断成半句话，改为更稳的本地温和总结。
- 保持原则：不能为了规避长内容失败而删减用户确认阅读范围。

修改后结果：

- 已强化 `daily_summary_v1` 的 JSON-only 约束：只允许返回一个合法 JSON object，不允许 Markdown、代码块、解释文字或额外字段。
- 已优化长内容 fallback：从“截取原文前 80 字”改为抽取完整句子；复测中不再出现半句话截断。
- 小样本复测 DS-04 仍触发 fallback，原因从首轮 `schema_error` 变为 `provider_error`。这说明长内容 live 稳定性还没有彻底解决，但用户侧 fallback 体验已改善。
- 下一步如果继续优化，应增加 JSON 修复 / 一次重试层，而不是删减用户确认阅读范围。

案例价值：

这个 Bad Case 能体现 AI PM 对“长上下文 + 结构化输出 + 成本延迟”的真实权衡，不是只展示成功样例。

## 典型 Bad Case 2：模糊短问没有被直接问拦截

功能：AI 直接问  
caseId：DQ-09  
输入：

```text
这个什么意思
```

预期：不调用 live，提示用户补充概念或使用“基于原文回答”。  
实际：进入 live，并返回“没有上下文我无法准确回答”，但 `needsContext=false`、`suggestContextMode=false`。

问题表现：

- 模型意识到缺上下文，但接口层没有把它识别为需要上下文的问题。
- 返回字段和产品行为不一致：文本在说缺上下文，结构字段却没有建议切换。
- 这会削弱“直接问”和“基于原文回答”的功能边界。

问题归因：

- 输入规范化规则对“这段 / 这里 / 原文”等关键词拦截有效，但对“这个什么意思”这类口语化模糊短问覆盖不够。
- 前置拦截阈值偏窄，仅靠长度判断不足。

修改策略：

- 扩展上下文依赖表达：这个什么意思、这是什么意思、这是什么、这个怎么理解。
- 对“指示代词 + 意思 / 理解 / 为什么”类问题直接返回 `needsContext=true`。
- 前端提示应引导用户：如果问一个术语，请写出术语；如果问当前内容，请用“基于原文回答”。

修改后结果：

- 已扩展模糊短问拦截规则，覆盖“这个什么意思”“这是什么意思”“这个怎么理解”等表达。
- 小样本复测 DQ-09 已返回 `mode=mock`、`reason=needs_context`，没有进入 live。
- 返回结构已变为 `needsContext=true`、`suggestContextMode=true`，会引导用户使用“基于原文回答”。

案例价值：

这个 Bad Case 说明 AI 产品不是只看模型能不能答，还要看输入路由和功能边界是否符合用户心智。

## 典型 Bad Case 3：部分复杂输入未按预期切 pro

功能：AI 直接问 / AI 今日总结  
相关 case：DQ-05、DS-03、DS-05  
预期：概念对比、概念密集或抽象总结更适合 pro。  
实际：部分样例仍由 flash 处理。

问题表现：

- DQ-05 “认知负荷和注意力残留有什么区别？”实际走 flash，输出可用，但预期应走 pro。
- DS-03 概念密集总结实际走 flash，输出尚可，但可能在真实复杂文本里不稳定。
- DS-05 抽象内容总结实际走 flash，质量可接受，但路由策略偏保守。

问题归因：

- 当前模型路由更依赖输入长度和有限复杂关键词。
- “区别 / 对比 / 抽象概念整合”这类复杂度信号没有完全纳入路由规则。

修改策略：

- 将“区别、对比、关系、为什么、分析、机制、影响”等纳入复杂问题路由关键词。
- 今日总结可结合段落数、概念密度和抽象词密度判断是否切 pro。
- 保持成本意识：不是所有概念问题都切 pro，优先处理确实需要比较和推理的输入。

修改后结果：

- 已扩展复杂问题路由关键词，DQ-05 “认知负荷和注意力残留有什么区别？”复测后切到 `pro`，thinking enabled。
- 同时发现“影响”如果作为全局复杂词，会让普通短总结误切 pro；已收窄为仅直接问使用，避免不必要成本。
- DS-01 / DS-07 复测显示短内容今日总结走 `flash`，相同输入二次请求命中缓存，`cached=true`。

案例价值：

这个 Bad Case 能体现模型路由不是一次写死，而是需要根据真实评测样例持续校准。

## 下一步迭代建议

1. 优先修复直接问的模糊短问拦截，保护“直接问 / 基于原文回答”的边界。
2. 优化直接问展示层级，让 answer、example、returnHint 更适合阅读中快速扫读。
3. 调整模型路由关键词，让对比、分析、机制类问题更容易切 pro。
4. 针对长内容今日总结增加结构化输出稳定性方案。
5. 继续保留 mock 默认模式，live 作为作品集验证补充。

## 总结表达

这轮评测证明：当前 AI 能力不是只停留在“能调通 API”，而是已经进入输出质量评估阶段。本轮 AI 评测不是为了证明模型完美，而是为了发现真实上线前必须处理的边界、路由和 fallback 问题。我用真实用户反馈反推评测重点，再通过 live 样例检查模型路由、结构化输出、边界拦截和 fallback。发现的 Bad Case 也不急着掩盖，而是转化成下一轮产品和工程迭代任务。
